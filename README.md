# Task-Tracker

Простой и удобный канбан-трекер задач в браузере. Позволяет организовывать задачи по колонкам, перетаскивать их, назначать метки, отслеживать прогресс и историю изменений. Работает без сервера, без регистрации, без ключей API.

## Возможности

- Канбан-доска с неограниченным количеством колонок
- Добавление, удаление и переименование колонок
- Создание, редактирование и удаление карточек
- Drag-and-drop для карточек и колонок
- Цветные метки для карточек
- Выбор цвета колонки
- Поиск по названиям задач
- Прогресс-бар показывает процент задач в выбранной колонке
- Выбор колонки для расчёта прогресса
- История действий
- Тёмная тема с анимированным переключателем

## Технологии

- HTML5
- CSS3 (переменные, тёмная тема)
- JavaScript (без фреймворков и сборки)
- localStorage для хранения задач, колонок и истории

## Зачем этот проект

Я пробовал вести задачи в Trello, Notion и обычных заметках. Trello перегружен — половина интерфейса не нужна для личных задач. Notion слишком гибкий: вместо работы начинаешь настраивать систему. Заметки не дают структуры и не показывают движение задачи по этапам.

Захотелось простой инструмент, в котором есть только то, что реально нужно для ведения личных задач:

- канбан-доска, чтобы видеть движение, а не статичный список;
- метки, чтобы разделять задачи по темам;
- прогресс, чтобы понимать, сколько осталось;
- история, чтобы вспомнить, что и когда менялось.

Task-Tracker решает три задачи:

- Быстро создать задачу и положить её в нужную колонку
- Двигать задачи по этапам через drag-and-drop
- Видеть прогресс по выбранной колонке и не терять контекст

Это личный инструмент, которым я пользуюсь каждый день. Поэтому все решения в проекте продиктованы реальным сценарием использования, а не абстрактными требованиями.

## Продуктовые решения

Почему именно такой набор фич и такой интерфейс:

- **Канбан вместо списка.** Задачи имеют состояния. Список не показывает движение — канбан показывает. Это снижает когнитивную нагрузку: достаточно взглянуть на доску, чтобы понять, где что находится
- **Неограниченное количество колонок.** Жёсткие «To Do / Doing / Done» подходят не всем. Кто-то ведёт «Идеи / В работе / На ревью / Готово». Гибкость здесь важнее простоты, потому что каждый ведёт свои задачи по-своему
- **Drag-and-drop для карточек и колонок.** Перетаскивание — самый естественный способ менять статус. Клик по меню медленнее и требует больше внимания. То же для колонок: если порядок этапов поменялся, его должно быть легко перестроить
- **Цветные метки для карточек.** Позволяют различать задачи по темам без чтения текста. Красная — срочное, синяя — работа, зелёная — личное. Глаз цепляется за цвет быстрее, чем за слово
- **Прогресс-бар по выбранной колонке.** Не «сколько всего сделано», а «сколько сделано в этом этапе». Это честнее: работа над задачей — это движение по этапам, а не бинарное «сделано / не сделано». Пользователь сам выбирает, по какой колонке считать прогресс
- **История действий.** Позволяет вернуться и понять, что менялось. Особенно полезно, когда ведёшь несколько проектов параллельно и через неделю не помнишь, почему задача оказалась в другой колонке
- **Тёмная тема по умолчанию.** Стандарт для инструментов, в которых работают подолгу. Светлая тема остаётся для презентаций
- **localStorage вместо сервера.** Продукт не требует регистрации и работает у любого, кто скачал репозиторий. Для личного трекера сервер не нужен — это осознанный выбор, а не ограничение

## Метрики продукта

Как я оценивал бы успех этого инструмента, если бы развивал его как продукт:

- **Activation.** Доля пользователей, которые создали хотя бы одну задачу в первую сессию. Если задача не создана, трекер не начал работать
- **Retention.** Возвращаются ли пользователи на следующий день и через неделю. Ключевая метрика: если не возвращаются, сценарий неудобен или не нужен
- **Среднее число задач на пользователя.** Если задач мало, трекер не стал рабочим инструментом, а остался экспериментом
- **Использование drag-and-drop.** Если пользователи не перетаскивают карточки, значит, они не двигают задачи по этапам — и трекер не выполняет главную функцию
- **Использование истории действий.** Показывает, возвращаются ли пользователи к прошлым изменениям. Если нет — функция избыточна или непонятна
- **Создание дополнительных колонок.** Если пользователи добавляют свои колонки, значит, стандартных не хватает — и продукт помогает подстроить процесс под себя
